# PDF 脚注のページ下部配置 — 設計

状態: 実装済み。変更点: 印刷しない領域の印は属性 `data-pdf-footnotes` のみで、オプションは足していない。対象: `src/cpp/renderers/pdf_renderer.cpp`、`packages/html-to-image/src/markdown*.ts`。

## 目的

Markdown の脚注(`[^1]`)を、参照があるページの下部に出す。今は文書末の `section.footnotes` に
まとまる(`markdown-blocks.ts` の `createFootnotes`)。

## 今の PDF エンジンの前提

- 文書全体を 1 回レイアウトし、`plan_page_cuts` が決めたページ先頭の y(`PageCut.offset`)で切り出す。
- ページの描画は `draw_band(top, bottom, doc_offset)`。文書の帯を、任意の位置にずらして描ける。
  表の見出し行の繰り返し(`PageCut.header_*`)が、すでにこれで「ページ上部に別の場所の帯を描く」を行っている。
- ページの高さの予約には先例がある。`limit = pos + area_height - header_height`。
- 見出しやリンクの飛び先ページは `pages[i].offset <= top` で求めている。

## 方針: 本体は文書内に置き、ページごとに帯を描き直す

標準の `float: footnote` のように、レイアウトを作り替えない。

1. 脚注の本体(`li`)は、今までどおり文書の末尾の領域に置く。領域には `data-pdf-footnotes` を付ける。
2. エンジンは、その領域の上端を「印刷する文書の終わり」(`doc_height`)にする。領域そのものは印刷されない。
3. ページを区切るとき、そのページに参照(`a[href="#fn-N"]`)が入るなら、対応する `li#fn-N` の帯の高さを下部に予約する。
4. 描画では、本文の帯を描いたあと、予約した領域の上に区切り線を引き、各 `li` の帯を `draw_band` で描き直す。

利点: 脚注の本文は litehtml が本文と同じ幅・同じ書式でレイアウト済みなので、別の文書を作らなくてよい。

## 変更点

### 1. 検出(レイアウト後)

- `collect_footnotes(root)`: `data-pdf-footnotes` の領域を探し、子の `li[id]` ごとに
  `{id, top, bottom}` を集める。
- 参照は `a[href^="#"]` のうち、飛び先の id が上の `li` のもの。参照の y は、アンカーの最初の行の上端。
  既存の `collect_link_boxes` と同じ走査で足りる。
- 同じ脚注への参照が複数あるときは、最初の参照があるページにだけ出す。

### 2. 計画(`plan_page_cuts`)

引数に脚注の表(参照 y の昇順と、脚注の高さ)を足す。`PageCut` には `footnote_ids` と `footnote_height` を足す。

ページ先頭 `pos` ごとに:

1. `cut0` = 今の手順で出す切れ目(`limit = pos + area - header_height`)。
2. `R0` = `[pos, cut0)` に初参照がある脚注の高さの合計 + 区切り線の高さ。なければ 0 で、今と同じ。
3. `R0 > 0` なら `limit' = limit - R0` で手順をやり直し、切れ目 `cut1` を出す。`cut1 <= cut0` なので、
   `[pos, cut1)` の参照は `[pos, cut0)` の部分集合になり、予約 `R1 <= R0` で収まる。
   ページには実際に入る `R1` だけを予約として記録する(少し余白ができるのは許容)。
4. 脚注 1 件が単独でページに入らないとき(下の「制限」)は、その脚注の参照を含む行をそのページに入れない。

orphans / widows / `break-inside` の各手順は `limit` だけを見ているので、変更は `limit` の差し替えで済む。

### 3. 描画

- 各ページで、本文の帯のあとに、区切り線と脚注の帯を描く。位置は、ページ内容領域の下端から `R1` を引いた y。
- 本文の帯の高さは `avail - R1` に切る。クリップが脚注の上に出ないようにする。
- 脚注の帯は `draw_band(li.top, li.bottom, doc_offset)` で、`doc_offset = li.top - 描画先の y`。

### 4. リンク・しおり

- 脚注への内部リンクの飛び先は、本文の末尾(印刷されない領域)を指してしまう。参照のあるページ(脚注を置いたページ)に付け替える。
- `heading_pages`(見出しの id とページの対応)は変更なし。印刷されない領域には見出しがない。
- 脚注から参照元に戻るリンク(`fnref-N-k`)は、本文側の id なので、そのまま使える。

### 5. 総ページ数

印刷する文書の終わりが領域の上端になるので、脚注の領域だけの最終ページは出なくなる。`{{totalPages}}` はそれに従う。

## JS 側(Markdown)

- `createFootnotes().list()` の `section.footnotes` に `data-pdf-footnotes` を付ける。
- 前書きのキー `footnotes: page | end` を足す。既定は `end`(今と同じ)。`book` と `manual` の既定を `page` にするかは別に決める。
- `page` のときだけ `renderOptions.pdfFootnotes = true` を渡す。オプションが `false` なら `data-pdf-footnotes` は無視され、末尾に出る。
- ブラウザの `markdownToHtml`(PDF にしない経路)は変えない。

## 制限(初版)

- ページより高い、または 1 ページの 3 分の 1 より高い脚注は、ページ下部に置かない。その文書では `end` に戻し、警告を出す。
  ページをまたぐ脚注(続きを次のページに出す)は、後続の課題とする。
- 表の中の参照は対象外(行が分割単位なので、行ごとに参照を数えるのは後続)。
- 脚注の中の脚注は対象外。

## テスト

- C++ の単体: 参照の位置と高さの表から `plan_page_cuts` が出す切れ目(参照が 1 ページに 0 件・1 件・複数件、ページ境界の直前に参照)。
- 可視テスト(`regression.test.ts`): pdfjs で、脚注の本文の y が参照のあるページの下部にあること、そのページに本文が重ならないこと、`end` では末尾にあること。
- テンプレートの指紋: 脚注付きの文書を 1 件足して、`book` と `manual` で記録する。
- リンク: 脚注の参照が、脚注を置いたページを指すこと。
